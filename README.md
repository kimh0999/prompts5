# 프롬프트 관리 프로그램

자주 쓰는 생성형 AI 프롬프트를 한곳에 모아 두고, **분류하고 검색해서 바로 꺼내 쓰는** 터미널 프로그램입니다.

- 프롬프트를 등록하고 카테고리·키워드·즐겨찾기로 찾습니다.
- 등록한 내용은 `prompts.json` 파일에 저장되어 다음 실행에도 남아 있습니다.
- 외부 패키지 없이 **Python 표준 기능만** 사용합니다. (Python 3.10 이상)

> Python 기본 문법과 Git 사용법을 익히기 위한 학습용 프로젝트입니다.
> 그래서 코드와 문서 모두 "왜 이렇게 했는지"를 함께 적어 두었습니다.

## 1. 빠른 시작

**필요한 것:** Python 3.10 이상 (메뉴 분기에 3.10부터 추가된 `match / case` 문법을 사용합니다)

```bash
py -3.13 main.py
```

버전 확인:

```bash
py -3.13 --version
```

> **주의**: 이 프로젝트를 개발한 환경에서는 `python` 명령이 Python 3.9를 가리켜
> `match` 문법에서 오류가 발생합니다. 시스템 기본 Python이 3.10 이상이라면
> `python main.py` 로도 실행할 수 있습니다.

처음 실행하면 저장 파일이 없으므로 기본 프롬프트 4개로 시작합니다.

```
  저장 파일이 없어 기본 프롬프트 4개로 시작합니다.

  계속하려면 Enter를 누르세요...
```

Enter를 누르면 화면이 정리되고 메인 메뉴가 나타납니다.

```
  ============================================================
                     프롬프트 관리 프로그램
  ============================================================
  [1] 프롬프트 추가         [5] 상세 보기
  [2] 전체 목록             [6] 즐겨찾기 변경
  [3] 카테고리별 조회       [7] 즐겨찾기 목록
  [4] 키워드 검색           [0] 종료
  ------------------------------------------------------------
  등록된 프롬프트 4개

  선택 >
```

번호를 입력해 기능을 고르고, 결과를 확인한 뒤 Enter를 누르면 다시 메뉴로 돌아옵니다.

## 2. 기능 한눈에 보기

| 번호 | 기능 | 설명 |
|---|---|---|
| 1 | 프롬프트 추가 | 제목·목적·카테고리·내용·태그·모델을 입력받아 등록 |
| 2 | 전체 목록 | 등록된 프롬프트를 표로 요약 표시 |
| 3 | 카테고리별 조회 | 카테고리를 골라 해당 프롬프트만 표시 |
| 4 | 키워드 검색 | 제목·목적·내용·태그에서 검색 (대소문자 구분 없음) |
| 5 | 상세 보기 | 번호로 골라 모든 정보와 내용 전문 표시 |
| 6 | 즐겨찾기 변경 | 즐겨찾기 상태를 켜고 끔 |
| 7 | 즐겨찾기 목록 | 즐겨찾기한 프롬프트만 모아서 표시 |
| 0 | 종료 | |

### 화면이 흘러가는 방식

```
메뉴 → 기능 실행 → 결과 표시 → Enter 대기 → 화면 지움 → 메뉴
                                    ↑
                       결과를 읽거나 복사할 시간을 줍니다
```

### 잘못 입력해도 종료되지 않습니다

아래 상황에서 프로그램이 멈추지 않고 안내 메시지를 출력한 뒤 메뉴로 돌아옵니다.

- 메뉴에 없는 번호 (`9`, `-1` 등)
- 숫자가 아닌 입력 (`abc`)
- 존재하지 않는 프롬프트 번호 (`999`)
- 제목·목적·내용 등의 빈 입력
- 카테고리 목록에 없는 번호 (`0`, `99` 등)

`Ctrl+C`로 중단해도 오류 화면 없이 정상 종료됩니다.

## 3. 사용 예시

### 전체 목록 (2번)

```
  전체 목록                                             총 4개
  ============================================================
  번호   제목                       카테고리     대상 모델
  ------------------------------------------------------------
     1 * IT 뉴스 요약 및 분류       요약·분석    ChatGPT
     2   ReqMate 요구사항 문서화    기획·문서화  Claude
     3   C 언어 코드 오류 분석      개발·코딩    Claude
     4   재고 부족 감지 자동화 설계 업무 자동화  ChatGPT
  ------------------------------------------------------------
  * 표시는 즐겨찾기입니다.

  계속하려면 Enter를 누르세요...
```

제목이 길면 `...`으로 줄여 표가 깨지지 않게 합니다.

### 프롬프트 추가 (1번)

내용은 여러 줄로 입력할 수 있습니다. 복사해둔 프롬프트를 통째로 붙여넣고
마지막에 `END`만 입력하면 됩니다.

```
  프롬프트 추가
  ============================================================
  제목 > 영어 이메일 작성
  목적 > 비즈니스 영어 메일 초안 작성

  카테고리를 선택하세요.
  ------------------------------------------------------------
  [1] 작성·콘텐츠           [5] 업무 자동화
  [2] 요약·분석             [6] 학습·교육
  [3] 개발·코딩             [7] 취업·커리어
  [4] 기획·문서화           [8] 기타
  ------------------------------------------------------------
  번호 > 1

  내용을 입력하세요.
  (입력을 마치려면 END만 적고 엔터를 누르세요)
  > 아래 내용을 정중한 비즈니스 영어 이메일로 바꿔줘.
  >
  > - 격식 수준을 상대에 맞게 조절
  > - 제목도 함께 제안
  >
  > 내용: [여기에 붙여넣기]
  > END
  태그 (쉼표로 구분) > 영어, 이메일, 번역
  대상 모델 (예: ChatGPT, Claude) > ChatGPT

  프롬프트가 추가되었습니다. (번호: 5)
```

### 키워드 검색 (4번)

제목·목적·내용·태그를 대소문자 구분 없이 검색합니다.

```
  키워드 검색
  ============================================================
  검색어 > it

  'it' 검색 결과                                        총 1개
  ============================================================
  번호   제목                       카테고리     대상 모델
  ------------------------------------------------------------
     1   IT 뉴스 요약 및 분류       요약·분석    ChatGPT
  ------------------------------------------------------------
  * 표시는 즐겨찾기입니다.
```

### 상세 보기 (5번)

```
  프롬프트 상세 보기
  ============================================================
  번호 > 1

  IT 뉴스 요약 및 분류                                     1번
  ============================================================
  카테고리  요약·분석
  목적      IT 뉴스의 핵심 내용과 기술 동향 파악
  대상 모델 ChatGPT
  태그      IT, 뉴스, 요약, 동향
  즐겨찾기  아니오
  ------------------------------------------------------------

아래 IT 뉴스 기사를 읽고 다음 형식으로 정리해줘.
1. 한 줄 요약
2. 핵심 내용 3가지
3. 관련 기술 분야 분류
4. 개발자 입장에서 주목할 점

기사: [기사 본문을 여기에 붙여넣기]

  ------------------------------------------------------------
```

프롬프트 내용만 들여쓰기 없이 출력됩니다. 복사해서 그대로 붙여넣기 위해서입니다.

## 4. 데이터 저장 방식

프롬프트는 프로그램을 종료해도 사라지지 않습니다. **`prompts.json`** 파일에 저장되며,
다음 실행 때 이 파일에서 다시 읽어옵니다.

| 항목 | 내용 |
|---|---|
| 저장 위치 | 항상 `main.py`와 같은 폴더 |
| 저장 시점 | 프롬프트 추가(1번), 즐겨찾기 변경(6번) 직후 **즉시** |
| 파일 형식 | JSON (`ensure_ascii=False`, `indent=2` — 한글 그대로, 사람이 읽을 수 있게) |
| Git 추적 | 제외 (`.gitignore`에 등록 — 소스가 아닌 사용자 데이터이므로) |

### 시작할 때의 세 가지 경우

| 상황 | 동작 |
|---|---|
| 파일이 있고 정상 | 파일에서 프롬프트를 불러옴 |
| 파일이 없음 | 기본 프롬프트 4개로 시작하고 `prompts.json`을 새로 만듦 |
| 파일이 깨짐 | 원본을 `prompts.broken.json`으로 백업한 뒤, 기본 프롬프트 4개로 새로 만듦 |

깨진 파일을 만났을 때의 안내는 다음과 같습니다.

```
'prompts.json' 내용이 프롬프트 목록의 형식과 맞지 않습니다.
깨진 파일은 'prompts.broken.json'(으)로 옮겨 두었습니다.
기본 프롬프트 4개로 새로 시작합니다.
```

> 깨진 파일이 또 생기면 이전 `prompts.broken.json`은 덮어써집니다.
> 내용을 되살려야 한다면 다음 실행 전에 따로 복사해 두세요.

### 저장 파일 예시

```json
[
  {
    "id": 1,
    "title": "IT 뉴스 요약 및 분류",
    "category": "요약·분석",
    "tags": [
      "IT",
      "뉴스"
    ],
    "favorite": false
  }
]
```

## 5. 데이터 구조

프롬프트는 **리스트 안에 딕셔너리**를 담는 형태로 다룹니다.
이 구조를 그대로 JSON 파일에 저장합니다.

```python
{
    "id": 1,
    "title": "IT 뉴스 요약",
    "category": "요약·분석",
    "purpose": "IT 뉴스의 핵심 내용과 기술 동향 파악",
    "content": "실제로 복사하여 사용할 프롬프트 내용",
    "tags": ["IT", "뉴스", "요약"],
    "model": "ChatGPT",
    "favorite": False
}
```

| 항목 | 자료형 | 의미 |
|---|---|---|
| `id` | `int` | 프롬프트를 구분하는 번호 (기존 최대값 + 1로 자동 부여) |
| `title` | `str` | 프롬프트 이름 |
| `category` | `str` | 사용 목적에 따른 분류 |
| `purpose` | `str` | 프롬프트를 사용하는 이유 |
| `content` | `str` | 실제 프롬프트 내용 (여러 줄 가능) |
| `tags` | `list[str]` | 검색에 사용할 세부 키워드 |
| `model` | `str` | 사용할 생성형 AI |
| `favorite` | `bool` | 즐겨찾기 여부 |

프로그램을 처음 시작하면 기본 프롬프트 4개가 등록되어 있습니다.

## 6. 카테고리

결과물의 형태가 아니라 **사용 목적**을 기준으로 분류합니다.
카테고리는 **이 목록에서 번호로만 선택**할 수 있고, 직접 입력할 수 없습니다.

```python
CATEGORIES = [
    "작성·콘텐츠",
    "요약·분석",
    "개발·코딩",
    "기획·문서화",
    "업무 자동화",
    "학습·교육",
    "취업·커리어",
    "기타"
]
```

## 7. 프로젝트 구조

```
python-prompt/
├── .gitignore      # Git이 추적하지 않을 파일 목록
├── README.md       # 이 문서
├── main.py         # 프로그램 전체 (약 580줄)
├── prompts.json    # 저장 파일 (실행하면 자동 생성, Git 추적 제외)
└── prompts.broken.json  # 저장 파일이 깨졌을 때만 생기는 백업
```

`main.py` 하나로 이루어져 있으며, 함수 구성은 다음과 같습니다.

**데이터 저장·불러오기**

| 함수 | 역할 |
|---|---|
| `create_default_prompts()` | 기본 프롬프트 4개 생성 |
| `save_prompts()` | JSON 파일로 저장 (데이터가 바뀔 때마다 호출) |
| `load_prompts()` | 시작할 때 JSON 파일에서 불러오기 |
| `has_prompt_format()` | 프롬프트 하나의 항목과 자료형 확인 |
| `has_prompt_list_format()` | 읽어온 데이터 전체가 프롬프트 목록인지 확인 |
| `start_with_defaults()` | 깨진 파일을 백업하고 기본값으로 새로 시작 |

**입력 처리**

| 함수 | 역할 |
|---|---|
| `get_non_empty_input()` | 빈 값을 거부하는 입력 |
| `get_multiline_input()` | `END`가 나올 때까지 여러 줄 입력 |
| `select_category()` | 정해진 카테고리 목록에서 선택 |
| `find_prompt_by_id()` | 번호 입력·검증·조회 (2개 기능이 공유) |

**화면 출력**

| 함수 | 역할 |
|---|---|
| `clear_screen()` | 메뉴로 돌아갈 때 이전 화면 지우기 |
| `wait_for_enter()` | 결과를 다 읽을 때까지 대기 |
| `text_width()`, `fit()` | 한글 폭을 고려한 표 정렬과 말줄임 |
| `print_section()` | 화면 제목 줄 출력 |
| `print_two_columns()` | 메뉴·카테고리를 좌우 두 줄로 출력 |
| `print_prompt_table()` | 목록 표 출력 (4개 기능이 공유) |

**기능**

| 함수 | 역할 |
|---|---|
| `add_prompt()` | 프롬프트 추가 |
| `show_prompt_list()` | 전체 목록 |
| `show_by_category()` | 카테고리별 조회 |
| `search_prompts()` | 키워드 검색 |
| `show_prompt_detail()` | 상세 보기 |
| `toggle_favorite()` | 즐겨찾기 추가·해제 |
| `show_favorites()` | 즐겨찾기 목록 |
| `show_menu()`, `main()` | 메뉴 출력과 반복 루프 |

## 8. 설계 메모 — 왜 이렇게 만들었나

프로그램을 쓰는 데는 필요하지 않지만, 각 결정의 이유를 남겨 둡니다.
읽고 싶은 항목만 펼쳐 보세요.

<details>
<summary><b>결과를 보여준 다음이 아니라, Enter를 누른 다음에 화면을 지우는 이유</b></summary>

<br>

결과가 나오자마자 메뉴를 다시 출력하면, 방금 본 내용이 위로 밀려 올라가고 화면이
계속 길어집니다. 그렇다고 결과를 보여준 직후 화면을 지우면 읽을 수가 없습니다.
그래서 **Enter를 누른 다음에** 지웁니다.

</details>

<details>
<summary><b>표에 <code>★</code> 대신 <code>*</code>를, <code>─</code> 대신 <code>-</code>를 쓰는 이유</b></summary>

<br>

`★` `·` `─` 같은 문자는 유니코드에서 **폭이 모호한(Ambiguous) 문자**로 분류됩니다.
터미널과 글꼴에 따라 한 칸으로도 두 칸으로도 그려져서, 이런 문자를 표 안에 넣으면
줄마다 열이 어긋납니다. 그래서 정렬에 영향을 주는 자리에는 ASCII 문자만 씁니다.

</details>

<details>
<summary><b>상세 보기에서 프롬프트 내용만 들여쓰기 없이 출력하는 이유</b></summary>

<br>

앞에 공백이 붙으면 복사해서 붙여넣을 때 그 공백까지 따라갑니다.
프롬프트는 복사해서 쓰라고 저장하는 것이므로, 내용 부분만 들여쓰기를 빼둡니다.

</details>

<details>
<summary><b>저장 파일 경로를 <code>Path(__file__).with_name()</code>으로 잡는 이유</b></summary>

<br>

```python
DATA_FILE = Path(__file__).with_name("prompts.json")
```

`DATA_FILE = "prompts.json"`처럼 이름만 적으면 기준이 `main.py`의 위치가 아니라
**명령어를 실행한 현재 폴더**가 됩니다. 그러면 어느 폴더에서 실행하느냐에 따라
저장 파일이 여기저기 흩어지고, 이전에 추가한 프롬프트가 보이지 않게 됩니다.

`__file__`은 실행 중인 파이썬 파일의 경로이고, `with_name()`은 그 경로에서
파일 이름만 바꿉니다. 두 개를 합치면 `main.py` 옆 경로가 됩니다.

</details>

<details>
<summary><b>종료할 때 한 번에 저장하지 않고, 바뀔 때마다 즉시 저장하는 이유</b></summary>

<br>

`Ctrl+C`로 중단하거나 프로그램이 예기치 않게 멈춰도 작업한 내용이 남아 있게 하기
위해서입니다. 저장이 일어나는 곳은 프롬프트 추가(1번)와 즐겨찾기 변경(6번) 두 군데입니다.

</details>

<details>
<summary><b>깨진 저장 파일을 덮어쓰지 않고 이름을 바꿔 남겨 두는 이유</b></summary>

<br>

그냥 두면 다음 실행에서도 같은 경고가 계속 나오고, 그렇다고 바로 덮어쓰면
원본을 되살릴 수 없습니다. 이름을 바꿔 두면 둘 다 피할 수 있습니다.

```
깨진 prompts.json
  → prompts.broken.json 으로 백업 (원본 보존)
  → 기본 프롬프트로 prompts.json 새로 생성
```

</details>

<details>
<summary><b>항목 이름만이 아니라 자료형까지 확인하는 이유</b></summary>

<br>

"깨졌다"고 보는 경우는 두 가지이고, 둘 다 걸러냅니다.

**1. JSON 문법이 맞지 않는 경우** — 파일을 잘못 편집한 경우 등

**2. 문법은 맞지만 값의 자료형이 다른 경우**

항목 이름이 있는지만 확인하면 아래 같은 데이터가 그대로 통과해, 나중에 목록을
출력하거나 프롬프트를 추가할 때 프로그램이 중단됩니다.

```json
{
  "id": "첫 번째",
  "title": 123,
  "tags": "Python",
  "favorite": "false"
}
```

| 항목 | 있어야 하는 자료형 |
|---|---|
| `id` | 정수 (`True`/`False`는 정수로 취급되므로 제외) |
| `title`, `category`, `purpose`, `content`, `model` | 문자열 |
| `tags` | 문자열만 담긴 목록 |
| `favorite` | `True` 또는 `False` |

</details>

<details>
<summary><b>카테고리를 직접 입력할 수 없게 만든 이유</b></summary>

<br>

- **같은 분류가 여러 개로 쪼개집니다.** `데이터 분석`, `데이터분석`, `데이터·분석`은
  사실상 같은 분류인데 프로그램은 서로 다른 카테고리로 취급합니다.
- **직접 만든 카테고리는 목록에 나타나지 않습니다.** 나중에 카테고리별 조회(3번)를
  하려면 사용자가 그 이름을 정확히 기억해서 다시 입력해야 합니다.

참고로 `작성·콘텐츠`는 원래 `콘텐츠 제작`이었습니다. 이메일 작성이나 문장 다듬기처럼
"무언가를 만들어내는" 프롬프트를 더 자연스럽게 담기 위해 이름을 바꿨습니다.

</details>

## 9. Git 작업 기록

기본 브랜치는 `main`이며, **전체 목록 보기 기능**은 별도 브랜치에서 개발한 뒤 병합했습니다.

```bash
# 1. main에서 기능 브랜치를 만들고 이동
git checkout -b feature/prompt-list

# 2. 브랜치에서 전체 목록 보기 기능 구현 후 커밋
git add main.py
git commit -m "feat: 전체 프롬프트 목록 보기 기능 구현"

# 3. main으로 돌아와 병합
git checkout main
git merge --no-ff feature/prompt-list
```

`--no-ff` 없이 병합하면 Git이 커밋을 일직선으로 이어 붙여
**브랜치를 만들었다는 기록이 그래프에서 사라집니다.**
`--no-ff`를 붙이면 병합 커밋이 따로 생겨 분기와 병합 흔적이 남습니다.

```
*   merge: feature/prompt-list 브랜치 병합
|\
| * feat: 전체 프롬프트 목록 보기 기능 구현   <- feature/prompt-list
|/
*   feat: 프롬프트 추가 기능 구현             <- main
```

그래프는 아래 명령으로 확인할 수 있습니다.

```bash
git log --oneline --graph --decorate --all
```

### 커밋 규칙

기능 단위로 커밋하며, 메시지 앞에 작업 종류를 표시했습니다.

| 접두사 | 의미 |
|---|---|
| `chore:` | 설정·구조 등 기능 외 작업 |
| `feat:` | 새 기능 추가 |
| `test:` | 테스트와 그 과정에서 발견한 수정 |
| `docs:` | 문서 작업 |
| `merge:` | 브랜치 병합 |
